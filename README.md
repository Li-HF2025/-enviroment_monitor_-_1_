该项目是一个基于 STM32F103C8 与 ESP32-S3 的双板环境监测系统。

系统分为两部分：STM32 负责传感器采集与底层控制，ESP32-S3 负责联网、MQTT 上报、时间同步以及 LVGL 人机界面显示。两块板子通过 USART1/UART1 进行双向通信，整体采用自定义二进制协议进行数据交换。

## 项目目标

项目的核心目标是把“传感器采集 - 数据解析 - 本地显示 - 云端上报 - 远程控制”串成一条完整链路：

1. STM32 采集分贝、温湿度等数据，并按协议回传给 ESP32-S3。
2. ESP32-S3 将数据解析后显示到触摸屏界面，并同步上传到 MQTT 平台。
3. ESP32-S3 也可以通过协议向 STM32 发送请求，控制传感器启停。
4. ESP32-S3 通过 Wi-Fi 获取网络时间，并将时间展示在界面上。

## 总体架构

### ESP32-S3 侧

ESP32-S3 使用 ESP-IDF 开发，主要承担以下职责：

1. 连接 Wi-Fi，作为整个系统联网入口。
2. 通过 MQTT 连接 OneNET 平台，发布温度、湿度、分贝等数据。
3. 驱动 LVGL 界面，在 2.8 英寸 ILI9341 触摸屏上显示数据。
4. 接收 STM32 通过串口回传的数据，并根据命令分发到不同业务任务。
5. 通过 SNTP 获取网络时间，驱动界面时钟更新。

### STM32 侧

STM32F103C8 使用 PlatformIO + STM32Cube/HAL + FreeRTOS，主要承担以下职责：

1. 控制和采集传感器。
2. 解析来自 ESP32-S3 的请求帧。
3. 通过响应帧返回实时数据。
4. 通过上报帧输出设备状态或执行结果。

## 主要功能

### 1. Wi-Fi 连接

ESP32-S3 以 STA 模式连接路由器，Wi-Fi 参数由 Kconfig 配置项提供，而不是写死在代码中。当前实现包含断线重试逻辑，达到最大重试次数后才判定连接失败，因此并不是“完全不能重连”，而是“可重试，但受最大次数限制”。

### 2. MQTT 云端通信

MQTT 部分基于 ESP-IDF 的 MQTT 客户端实现，连接 OneNET 物联网平台。

连接成功后，程序会：

1. 订阅命令主题，用于接收云端控制指令。
2. 订阅属性上报回包和属性设置主题，便于观察平台交互结果。
3. 将当前采集到的温度、湿度、分贝等数据组织成 JSON 后发布到属性上报主题。

上传的数据采用 JSON 格式，便于和云平台或后续的可视化工具对接。

### 3. LVGL 触摸屏界面

界面使用 SquareLine 生成，并由 ESP32-S3 在 2.8 英寸 SPI 触摸屏上渲染显示。屏幕硬件实际是 ILI9341 TFT 显示屏配合 XPT2046 触摸控制器，不是 OLED。

界面逻辑包括：

1. 主界面显示时间、温湿度、分贝等核心信息。
2. 点击时钟区域进入时间详情页，可显示当前日期与时间，并支持网络时间同步。
3. 存在空闲锁屏机制，默认 5 分钟无操作后进入锁屏。
4. 触摸活动会刷新空闲计时，解除锁屏后恢复主界面交互。
5. 已有温度和分贝详情页逻辑，后续可以继续扩展更多传感器页面。

### 4. 自定义串口协议

ESP32-S3 与 STM32 之间使用自定义二进制协议通信。这个协议是整个系统的控制中枢，因为所有“请求、响应、上报”都通过它传输。

协议帧格式如下：

SOF(0x55 0xAA) + Version + MsgType + Cmd + Seq + PayloadLen + Payload + Checksum + EOF(0x0D 0x0A)

其中：

1. `MsgType` 表示消息类型，包含请求、响应、上报三种。
2. `Cmd` 表示命令类型，例如测试命令、温度命令、分贝命令。
3. `Seq` 已在实现中保留并递增，当前业务对它的依赖不强，但协议层并不是“没用到”，而是“保留了扩展能力”。
4. `Checksum` 采用累加校验，覆盖版本号、消息类型、命令、序列号、长度和载荷数据。

这套协议的好处是结构清晰、解析简单，适合嵌入式设备之间做稳定的二进制通信。

### 5. 分贝检测

STM32 侧的分贝模块并不是直接“测出绝对分贝值”，而是通过 ADC 采样电压信号，再经过 DMA、滤波和映射估算出一个可显示的分贝值。

当前实现的关键流程是：

1. ADC1 采集 PB1 上的模拟输入，通道为 ADC1_IN9。
2. DMA 采用循环模式持续搬运采样数据。
3. 半满和全满回调触发任务通知。
4. 任务对半缓冲区求平均，再进行移动平均滤波和指数平滑。
5. 将最终结果通过响应帧发送给 ESP32-S3。

如果收到停用命令，STM32 会停止 DMA 采样，从而关闭该模块。

### 6. 温湿度检测

温湿度模块使用 DHT22，而不是泛泛的“单线传输协议传感器”。DHT22 在 PB0 上通过单总线时序通信，读取 40 位原始数据后解析温度和湿度。

当前流程是：

1. ESP32-S3 发送请求帧，要求 STM32 初始化或关闭 DHT22。
2. STM32 在使能状态下定时读取 DHT22 原始数据。
3. 读取成功后，STM32 通过响应帧返回温度和湿度。
4. ESP32-S3 收到后更新界面，并同步写入 MQTT 上报数据。

## 数据流

一条完整的数据链路如下：

1. STM32 采集传感器数据。
2. STM32 通过响应帧把数据发给 ESP32-S3。
3. ESP32-S3 串口任务解析协议帧，并把结果送入主任务队列。
4. 主任务根据命令把数据分发到温湿度任务、分贝任务等。
5. 各业务任务更新 LVGL 数据，并触发 MQTT 上报。

控制链路则相反：

1. ESP32-S3 在界面上触发开关操作。
2. ESP32-S3 通过请求帧控制 STM32 的传感器模块。
3. STM32 解析请求后执行初始化、停止或其他动作。
4. STM32 返回响应或上报结果。

## 硬件连接

### ESP32-S3

1. UART1 TX/RX 用于和 STM32 通信。
2. SPI 总线驱动 ILI9341 LCD 和 XPT2046 触摸控制器。
3. Wi-Fi 用于联网、MQTT 和 SNTP。

### STM32F103C8

1. USART1 使用 PA9/PA10 和 ESP32-S3 通信。
2. DHT22 连接在 PB0。
3. 分贝模拟输入连接在 PB1，进入 ADC1_IN9。

## 开发环境

### ESP32-S3

1. 开发框架：ESP-IDF
2. 主要组件：Wi-Fi、MQTT、SNTP、LVGL、ESP LCD、ESP Touch

### STM32F103C8

1. 开发环境：PlatformIO
2. 框架：STM32Cube HAL
3. 调度：FreeRTOS

## 构建与运行

### ESP32-S3

进入 ESP 目录后，建议先设置目标芯片，再编译烧录：

```bash
idf.py set-target esp32s3
idf.py menuconfig
idf.py build flash monitor
```

在 `menuconfig` 中需要配置的内容通常包括 Wi-Fi、MQTT 和屏幕相关参数。

### STM32F103C8

进入 STM 目录后使用 PlatformIO 构建和烧录：

```bash
pio run
pio run -t upload
pio device monitor
```

如果你使用的是 STM32CubeIDE，也可以直接导入 STM 工程进行编译和下载。

## 命令与数据定义

当前协议中已定义的主要命令包括：

1. `CMD_TEST`：测试通信是否正常。
2. `CMD_TEMPERATURE`：温湿度传感器控制与数据回传。
3. `CMD_DB`：分贝模块控制与数据回传。
4. `CMD_LIGHT`：预留命令，当前工程中尚未形成完整实现。

消息类型包括：

1. `MSG_TYPE_REQUEST`：请求。
2. `MSG_TYPE_RESPONSE`：响应。
3. `MSG_TYPE_REPORT`：上报。

## 代码结构概览

1. `ESP/main/main.c`：ESP32-S3 主入口，初始化串口、网络、MQTT 和屏幕。
2. `ESP/main/components/my_serial`：ESP 端串口协议收发。
3. `ESP/main/components/my_wifi`：Wi-Fi STA 连接逻辑。
4. `ESP/main/components/my_mqtt`：OneNET MQTT 连接与属性上报。
5. `ESP/main/components/my_screen`：屏幕、触摸和 LVGL 相关逻辑。
6. `STM/Core/Src/MySrc/mySerial.c`：STM32 端串口协议收发。
7. `STM/Core/Src/MySrc/main_task.c`：STM32 端主任务与命令分发。
8. `STM/Core/Src/MySrc/db.c`：分贝采集、滤波和上报。
9. `STM/Core/Src/MySrc/temperature.c`：DHT22 读取、解析和上报。

## 说明

本项目的设计思路是“ESP 做上位机，STM 做下位机”。ESP 负责更复杂的交互、显示和联网，STM 负责更稳定的传感器控制和实时采集。这样的分工可以把 UI、云端和底层采样解耦，后续扩展新传感器时也更容易。
